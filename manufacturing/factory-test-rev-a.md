# Sheet 08 — Factory Test / Programming Fixture Rev.A

Status: **production-test architecture FROZEN Rev.A**. Exact pogo-pin fixture mechanics and automated tester hardware remain VALIDATE_MANUFACTURING.

## 1. Objective
Every assembled AudioPicture must be programmable, electrically screened and functionally calibrated through a repeatable production fixture.

No normal production step should require:
- soldering temporary wires;
- opening an already closed front assembly;
- manual probe placement on fine-pitch IC pins.

## 2. Fixture architecture
Rear-side bed-of-nails / pogo fixture contacts dedicated MAIN test pads.

Preferred sequence:
1. unpowered resistance/short screen;
2. controlled power application;
3. boot/recovery/programming;
4. rail tests;
5. MCU/memory;
6. Ethernet/PoE;
7. daughterboards/sensors;
8. voice/microphones;
9. radar;
10. amplifier/DML acoustic test;
11. calibration/identity programming;
12. final pass/fail record.

## 3. Required pogo pads
Minimum baseline:

| Pad | Net | Purpose |
|---|---|---|
| TP01 | GND | fixture reference |
| TP02 | GND | high-current/reference return |
| TP03 | +24V_RAW or controlled factory 24V injection | system power |
| TP04 | +24V_SYS | monitored rail |
| TP05 | +5V_SYS | rail test |
| TP06 | +3V3_SYS | rail test |
| TP07 | CHIP_PU / RESET | hard reset |
| TP08 | GPIO0 / BOOT | ROM boot |
| TP09 | UART_TX | debug/program |
| TP10 | UART_RX | debug/program |
| TP11 | I2C_SDA | bus/service |
| TP12 | I2C_SCL | bus/service |
| TP13 | AUD_BCLK | audio clock |
| TP14 | AUD_LRCLK | audio frame |
| TP15 | POWER_ALERT | power monitor interrupt |
| TP16 | ETH_INT | Ethernet interrupt |
| TP17 | RADAR_IRQ | radar interrupt |
| TP18 | AMP_FAULT | amplifier fault |
| TP19 | MIC_HW_EN | privacy power control verification |
| TP20 | STATUS_LED/service diagnostic | UI/service test |

USB D+/D- may use the external USB-C connector rather than pogo pads. If fixture programming through native USB proves more reliable, dedicated controlled-impedance fixture contacts may be added.

## 4. Factory power
Preferred fixture powers the unit through its normal input path whenever practical.

Tests:
- external 24 V through J2;
- PoE through a controlled PSE fixture.

TP03 direct injection is for engineering/diagnostic isolation only unless production safety analysis explicitly approves it.

The fixture must current-limit initial power-up to detect assembly shorts safely.

## 5. Unpowered screening
Before applying full power:
- check +24V_SYS to GND resistance window;
- check +5V_SYS to GND;
- check +3V3_SYS to GND;
- detect hard shorts;
- verify DML pair continuity/expected DC resistance window where fixture access permits.

Limits are learned from qualified golden units and design calculations, not arbitrary values.

## 6. Programming
Primary production programming:
- native USB ROM downloader through J6, or
- UART ROM downloader through TP09/TP10.

Fixture controls:
- CHIP_PU
- GPIO0.

Program:
- bootloader;
- partition table;
- factory/recovery image;
- production firmware;
- initial NVS structure.

Then verify flash CRC and PSRAM.

## 7. Device identity
Factory writes protected identity:
- product model: OS-PF320-V22
- unique UUID
- hardware revision
- MAIN PCB revision
- VOICE/RADAR/ENV board revisions where available
- Ethernet MAC / Wi-Fi MAC association
- manufacture date/lot
- calibration record version.

Do not overwrite Espressif factory MACs.

UUID may be derived/generated by manufacturing system but must be globally unique and recorded in production database.

## 8. Power tests
Measure:
- +24V_SYS
- +5V_SYS
- +3V3_SYS
- INA228 bus voltage/current/power sanity.

Validate:
- POWER_ALERT;
- 5V_PG;
- 3V3_PG;
- external-source presence;
- PoE presence;
- source handover on a sample/extended station.

Full dual-source handover may be an extended QA test rather than every-unit test if cycle time demands.

## 9. MCU tests
- reset/boot;
- flash;
- PSRAM;
- watchdog;
- NVS read/write;
- Wi-Fi scan/RSSI reference;
- BLE advertisement/provisioning;
- USB recovery;
- UART.

RF pass limits require a controlled antenna/test environment or statistical golden-unit limits.

## 10. Ethernet / PoE
Every unit:
- W5500 SPI register access;
- PHY link;
- DHCP/static fixture network;
- packet transmit/receive stress;
- MAC/identity association.

PoE station:
- 802.3af/at detection/classification;
- Ag53024 startup;
- +24V_POE;
- load sanity.

## 11. I2C / daughterboards
Enumerate and validate:
- INA228;
- TAS5825M;
- XVF3800 control interface;
- SHT45;
- OPT3004;
- any production board-ID mechanism.

Check for stuck SDA/SCL and unexpected addresses.

## 12. Voice / microphones
Test sequence:
1. enable +3V3_MIC through MIC_HW_EN;
2. verify four microphone channels active;
3. play calibrated acoustic stimulus;
4. measure channel sensitivity;
5. check channel mismatch/polarity;
6. verify XVF3800 processed output;
7. verify AEC-reference path;
8. verify raw measurement mode;
9. disable MIC_HW_EN;
10. confirm microphone data/signal disappears as expected.

Hardware privacy OFF test is mandatory on every unit.

## 13. Radar
- enable radar;
- reset;
- SPI identity/register access;
- IRQ;
- raw frame acquisition;
- known-target/motion sanity test.

Station should include a repeatable radar target/geometry or a dedicated radar QA station.

## 14. Amplifier / DML
Safe sequence:
1. TAS5825M held disabled;
2. configure known factory DSP profile;
3. enable at low gain;
4. channel continuity;
5. low-level sine/noise;
6. microphone/reference sensor captures response;
7. sweep each logical channel;
8. verify polarity/correlation;
9. distortion/noise window;
10. fault line check.

Do not run maximum-power audio in the general programming fixture.

Thermal/max-output testing belongs to qualification/sample QA.

## 15. Acoustic factory baseline
Every finished acoustic assembly receives a short factory sweep.

Store:
- left/right baseline response;
- channel sensitivity;
- gross resonance/fault indicators;
- DML calibration/profile version.

This is manufacturing calibration, not room calibration.

Room calibration occurs after installation.

## 16. Environmental sensors
SHT45:
- CRC-valid read;
- temperature/humidity sanity window.

OPT3004:
- dark/light fixture response.

Final fabric-specific lux coefficient may be written by product/front-artwork SKU.

## 17. Status / service UI
Verify:
- STATUS_LED;
- hidden service input/touch;
- pairing action;
- factory-reset action.

Fixture optical sensor may verify hidden LED operation if visual inspection is undesirable.

## 18. Pass/fail record
Manufacturing system records per UUID:
- firmware version;
- hardware revisions;
- test timestamp/station;
- rail measurements;
- network test;
- microphone matching;
- radar test;
- acoustic baseline;
- sensor status;
- calibration versions;
- PASS/FAIL and failure code.

Do not store unnecessary microphone recordings; store derived test metrics unless raw data is explicitly needed for engineering traceability.

## 19. Failure codes
Minimum structured categories:
- PWR_xxx
- MCU_xxx
- USB_xxx
- ETH_xxx
- POE_xxx
- I2C_xxx
- VOICE_xxx
- MIC_xxx
- RADAR_xxx
- AMP_xxx
- DML_xxx
- ENV_xxx
- CAL_xxx.

This makes production yield analysis actionable.

## 20. Fixture mechanics
Pogo pads:
- all on one accessible PCB side where possible;
- no pads under permanently inaccessible mechanical parts;
- sufficient diameter/annular clearance for production pogo tolerance;
- grouped logically;
- at least two fixture alignment/tooling references.

Fixture shall mechanically locate the PCB/product before pins compress.

## 21. Safety
The fixture may contain:
- 24 V high current;
- PoE input;
- exposed powered PCB.

Provide:
- current limiting;
- emergency stop for production station where appropriate;
- insulated operator-accessible surfaces;
- automatic power removal before fixture release.

## 22. Release gates
Factory Test becomes production FROZEN after:
1. pogo pad positions frozen with PCB layout;
2. programming method selected USB vs UART primary;
3. golden-unit limits collected;
4. automated test firmware implemented;
5. microphone acoustic fixture characterized;
6. radar fixture characterized;
7. test cycle-time target met;
8. manufacturing database/traceability format frozen;
9. false-pass/false-fail study completed;
10. pilot-run yield review.


## Rev.A production-test freeze — 2026-09-29

### Every-unit mandatory tests
Every manufactured unit must pass:
- unpowered rail short/resistance screen;
- controlled power-up/current sanity;
- +24V_SYS, +5V_SYS, +3V3_SYS measurement;
- CHIP_PU and GPIO0 hard-recovery control;
- flash/PSRAM verification;
- USB ROM recovery enumeration or UART ROM fallback;
- W5500 register/PHY/link/packet test;
- INA228 sanity;
- I2C enumeration and stuck-bus test;
- VOICE reset/IRQ and audio-stream sanity;
- **hardware microphone privacy OFF test**;
- radar enable/reset/SPI/IRQ sanity;
- TAS5825M identity/fault/low-level output test;
- left/right DML continuity and short acoustic sweep;
- SHT45 and OPT3004 sanity;
- STATUS_LED/service input;
- UUID/revision/calibration record write and readback.

### Safe-state test
Every unit shall verify that, with ESP32 held in reset:
- AMP_PDN remains inactive;
- MIC_HW_EN remains inactive;
- RADAR_EN remains inactive;
- RADAR_RST remains asserted;
- ETH_RST remains asserted;
- ETH_CS and RADAR_CS remain inactive.

This test validates the external hardware bias network, not firmware behavior.

### PoE test
Production PoE device is **Silvertel Ag53024**.
Every-unit PoE station verifies detection/classification, startup and +24V_POE/+24V_SYS sanity.

System continuous PoE application budget is **22.5 W maximum**. The production test shall not use a higher continuous load as an acceptance requirement.

Full-power PoE thermal endurance and source-handover cycling are qualification/sample-QA tests, not mandatory long-duration every-unit tests.

### Qualification / sample-QA tests
Move these out of the normal high-throughput fixture:
- maximum external-24V audio output/thermal soak;
- sustained 22.5 W PoE application load;
- repeated PoE/external source handover cycling;
- Wi-Fi/BLE controlled RF characterization;
- Ethernet long-duration stress;
- USB ESD;
- system EMC pre-compliance;
- DML high-level distortion/excursion;
- long-duration microphone/AEC characterization;
- calibrated radar target characterization;
- environmental chamber tests.

### Pogo-pad baseline
TP01..TP20 remain the minimum MAIN fixture set already defined in this document.

USB D+/D- use the external USB-C connector by default rather than consuming two additional pogo contacts.

TP03 direct +24V_RAW injection remains engineering/diagnostic only. Normal production power enters through the real external-input path or controlled PoE PSE so protection/source-selection circuitry is exercised.

### Privacy acceptance criterion
With MIC_HW_EN commanded OFF and during MCU reset, microphone power rail +3V3_MIC must collapse below the PCB-B microphone operating threshold within a validated timeout. No valid microphone stream may remain available.

The factory database records this as a dedicated pass/fail field, not merely as part of a generic VOICE test.

### Recovery acceptance criterion
A unit with intentionally invalid application firmware must remain recoverable through ESP32 ROM download mode using hardware GPIO0 + CHIP_PU controls. Recovery must not depend on the hidden service touch input or application firmware.

### Manufacturing status
Status: **READY_FOR_NATIVE_KICAD_CAPTURE_WITH_FIXTURE_LAYOUT_GATE**.

Remaining production-release gates:
1. final pogo coordinates/diameters;
2. fixture alignment/tooling geometry;
3. USB-vs-UART primary station method after cycle-time trials;
4. golden-unit electrical/acoustic limits;
5. automated test firmware;
6. characterized microphone/radar/acoustic fixtures;
7. pilot-run false-pass/false-fail study.
